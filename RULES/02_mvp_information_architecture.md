# MVP情報設計と実装整理

## 1. この文書の目的

`01_requirement_definition.md` で定めた要件を、MVP実装へ落とし込むための整理資料です。
画面、ユースケース、主要データ責務、実装優先順をまとめます。

## 2. MVPで成立させる体験

学習者はLINE公式アカウントからLIFFを開き、すぐに「今日の5問」を開始できる。
回答はその場で採点され、解説を確認でき、途中離脱しても復帰できる。

管理者は最低限、学習者一覧と基本的な学習状況を確認できる。

## 3. MVPの主要画面

### 3.1 学習者向け

- Home
  - 今日の学習導線を最優先で見せる
- 今日の5問
  - Session開始、設問表示、回答、採点、解説表示
- 学習履歴
  - 累計問題数、正答率、最終学習日時の確認
- 設定
  - 最低限のアカウント表示や利用状態確認

### 3.2 管理者向け

- Dashboard
  - 初期は簡易でもよいが、学習者一覧への導線を置く
- 学習者一覧
  - 学習者名、累計問題数、正答率、最終学習日時
- 学習者詳細
  - MVPでは簡易表示でもよい

## 4. MVP主要ユースケース

### 4.1 学習者

1. LINEからLIFFを開く
2. TenantとUserを識別する
3. 今日の5問セッションを取得または生成する
4. 問題をテンポよく解く
5. 回答ごとに採点と解説を確認する
6. 回答イベントを記録する
7. 途中離脱後に再開する

### 4.2 管理者

1. 管理UIへアクセスする
2. Tenant配下の学習者一覧を確認する
3. 最低限の学習状況を把握する

## 5. データ責務の最小整理

### 5.1 主要エンティティ

- PlatformAdmin
- Tenant
- User
- Membership
- LineConnection
- Course
- Category
- Unit
- Question
- Assignment
- LearningSession
- SessionQuestion
- AnswerEvent
- LearningProfile
- FeatureEntitlement

### 5.2 責務分離の要点

- Userの本人情報とTenant所属情報は分ける
- Session生成と問題選定は分ける
- Questionの形式と採点方式は分ける
- 回答記録と集計結果は分ける
- Feature判定はPlan名ではなくEntitlement経由にする

## 6. API責務の整理

MVPではエンドポイント名より責務分離を優先する。

### 6.1 認証 / 識別

- LIFFログイン状態の確認
- LINEユーザー識別
- Tenant文脈の確定
- Membershipと権限解決

### 6.2 学習セッション

- 今日の5問セッション取得または生成
- Session詳細取得
- Session再開
- 次に出す問題の取得

### 6.3 回答

- 回答送信
- 採点結果返却
- AnswerEvent永続化
- 冪等性付き再送

### 6.4 管理

- 学習者一覧取得
- 学習者別サマリ取得

## 7. UX / パフォーマンス前提

- LIFF起動後は可能な限り即時に問題を見せる
- 今日の5問は事前生成または事前取得を前提にする
- 学習中に次Session候補や復習候補をPrefetch可能な構造にする
- Local Stateで途中回答と未同期イベントを保持できるようにする
- AnswerEventには冪等性キーを持たせ、再送時の重複登録を防ぐ

## 8. 実装優先順

1. 認証とTenant識別の成立
2. Tenant / User / Membership / 権限モデル
3. Question / Session / AnswerEventの最小データモデル
4. 今日の5問の生成と取得
5. 7種問題の採点
6. LIFF学習UI
7. 回答途中保存と再開
8. 学習履歴サマリ
9. 管理者向け学習者一覧
10. Feature Entitlementの導入

## 9. 今後の詳細化候補

- ER図または論理データモデル
- 画面遷移図

- Local Stateと同期戦略

## 10. 変更管理メモ

MVP中に仕様を変える場合は、少なくとも次を確認してこの文書か `01_requirement_definition.md` へ反映する。

- 中心体験が「今日の5問」からぶれていないか
- Tenant境界と権限分離を弱めていないか
- 将来拡張を守るための分離を壊していないか
- MVP簡略化のために、後から戻しにくい近道を取っていないか
